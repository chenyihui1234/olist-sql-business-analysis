# Olist 电商数据集 · SQL 业务分析

用巴西电商 Olist 公开数据集，在本地 MySQL 上把常见业务分析场景逐个写出来跑通。
目的是练取数，也练口径 —— 同一个指标换种算法能差出好几倍，这个坑踩过一次就记住了。

## 数据集

| customers | 客户（含 customer_unique_id） | 99,441 |

| product_category_name_translation | 品类名英译 | — |

## 已完成的场景（20 个，全部实跑验证）

### 基础聚合

1. 各州客户数、订单量、GMV 排名
2. 订单状态分布与占比
3. 商品金额与运费对比，找出运费高于商品价的订单
4. 2017 年逐月 GMV 与订单量趋势
5. 各支付方式笔数、金额、占比、笔均金额

### 业务指标

6. 复购率（下单 ≥2 次的客户占比）
7. 每月新客 vs 老客拆分（新客 = 首单落在当月）
8. RFM 客户分层
9. 平均配送时长与准时率
10. 各品类平均评分与差评率，找出口碑最差的品类
11. 高评分与低评分订单的配送时长差异
12. 订单件数分布（1 件 / 2 件 / 3 件及以上）
13. 消费 TOP 10 客户画像（州、单数、客单、支付方式）

### 窗口函数（MySQL 8.0）

14. 每月 GMV 环比增长率（LAG）
15. 各品类销量排名 TOP 10（RANK 与 DENSE_RANK 对比）
16. 每个品类内销量前 3 的商品（ROW_NUMBER + PARTITION BY）
17. 帕累托分析：销量累计到 80% 需要几个品类（SUM() OVER 累计求和）
18. 卖家销售额百分位（PERCENT_RANK）
19. 每月 GMV 的 3 个月移动平均（ROWS BETWEEN 2 PRECEDING）
20. 订单按金额分低 / 中 / 高三档（NTILE）

## 跑出来的几个结论

- **帕累托**：销量累计到 80% 需要 **15 个品类**（第 15 个是 electronics，累计 80.0%）。全部 71 个品类里，前 15 个干了八成的量。
- **环比**：2016-09 平台刚起量，GMV 仅 354.75，环比数值失真；进入 2017 年从 13.7 万涨到 58 万+，4 月、6 月各回落一次。
- **移动平均**：3 个月均线把单月尖刺抹平，趋势比看单月清楚得多。
- **卖家**：头部卖家销售额 249,640.70，百分位为 0 —— 超越全平台 100% 的卖家。

## 几个容易算错的地方

这几个坑都是实跑时踩到的，写在前面免得再踩：

- **客户去重要用 `customer_unique_id`**，不能用 `customer_id`。后者是一单一码，同一个客户下三单就有三个 id，直接 COUNT 会把客户数算虚高，复购率更是会算出接近 0% 的荒谬结果。
- **JOIN 之后要防重复计数**。订单明细是一对多，聚合订单量记得 `COUNT(DISTINCT order_id)`，金额也别被明细行放大。
- **GMV 口径先定清楚**再动手：含不含运费、含不含取消单、按下单时间还是支付时间。口径不定就写 SQL，出来的数没法跟业务对。
