# Olist 数据集字段手册（刷题速查）

> 8张表，已全部导入本地 MySQL 的 `olist` 库。刷题时开着这份手册对照即可。

## 一、先记住三句口诀

1. **一切从 orders（订单表）出发**：算订单数、销售额、月度趋势，先看这张表。
2. **钱在 payments，货在 order_items，人在 customers，评分在 reviews**。
3. **customer_id 每单一个（假ID），customer_unique_id 才是真人**——算复购必须用后者。

## 二、表关系（怎么JOIN）

```
customers ──customer_id──> orders（1对多：一个客户多笔订单）
orders ──order_id──> order_items（1对多：一笔订单多个商品）
orders ──order_id──> payments（1对多：一笔订单可分多次支付）
orders ──order_id──> reviews（1对多：一笔订单可多条评论）
order_items ──product_id──> products（多对1：商品信息）
order_items ──seller_id──> sellers（多对1：卖家信息）
products ──product_category_name──> category_translation（多对1：葡语翻英语）
```

## 三、各表字段明细

### 1. customers 客户表（99441行）

| 字段 | 类型 | 含义 |
|------|------|------|
| customer_id | string | 客户订单级ID（**主键**，每个订单唯一） |
| customer_unique_id | string | 客户真实唯一ID（**算复购用这个**） |
| customer_zip_code_prefix | int | 邮编前3位 |
| customer_city | string | 城市 |
| customer_state | string | 州（如 SP、RJ、MG） |

### 2. orders 订单主表（99441行）

| 字段 | 类型 | 含义 |
|------|------|------|
| order_id | string | 订单号（**主键**） |
| customer_id | string | 关联客户表 |
| order_status | string | 订单状态（delivered已送达 / canceled已取消 / shipped已发货等） |
| order_purchase_timestamp | datetime | **下单时间**（算月度趋势用这个） |
| order_approved_at | datetime | 支付确认时间 |
| order_delivered_carrier_date | datetime | 交给物流时间 |
| order_delivered_customer_date | datetime | **送达客户时间**（算配送时长用这个） |
| order_estimated_delivery_date | datetime | 预计送达时间 |

> 常用组合：配送时长 = `DATEDIFF(order_delivered_customer_date, order_purchase_timestamp)`

### 3. order_items 订单商品明细（112650行）

| 字段 | 类型 | 含义 |
|------|------|------|
| order_id | string | 关联订单表 |
| order_item_id | int | 同一订单内的第几件商品（1,2,3...） |
| product_id | string | 关联商品表 |
| seller_id | string | 关联卖家表 |
| shipping_limit_date | datetime | 卖家发货截止时间 |
| price | decimal | **商品单价**（不含运费） |
| freight_value | decimal | 运费 |

> 算GMV/销售额：`SUM(price)` 或 `SUM(price + freight_value)`，按需求说明来。
> 注意：一笔订单有3件商品就是3行，**别直接COUNT这张表当订单数**。

### 4. payments 支付表（103886行）

| 字段 | 类型 | 含义 |
|------|------|------|
| order_id | string | 关联订单表 |
| payment_sequential | int | 第几笔支付（一笔订单可拆多笔） |
| payment_type | string | 支付方式（credit_card信用卡 / boleto巴西扫码付 / voucher代金券 / debit_card借记卡） |
| payment_installments | int | 分期期数 |
| payment_value | decimal | **该笔支付金额** |

> 算总支付金额：`SUM(payment_value)`。credit_card是最主流支付方式。

### 5. reviews 评价表（~100000行）

| 字段 | 类型 | 含义 |
|------|------|------|
| review_id | string | 评论ID |
| order_id | string | 关联订单表 |
| review_score | int | **评分1-5分**（算差评率：score=1 或 ≤2） |
| review_comment_title | string | 评论标题（葡语） |
| review_comment_message | string | 评论内容（葡语） |
| review_creation_date | datetime | 评论发布时间 |
| review_answer_timestamp | datetime | 商家回复时间 |

> 商家回复时长 = `DATEDIFF(review_answer_timestamp, review_creation_date)`

### 6. products 商品表（32951行）

| 字段 | 类型 | 含义 |
|------|------|------|
| product_id | string | 商品ID（**主键**） |
| product_category_name | string | 品类名（**葡语**，需JOIN category_translation翻译） |
| product_name_lenght | int | 商品名长度 |
| product_description_lenght | int | 描述长度 |
| product_photos_qty | int | 图片数量 |
| product_weight_g | int | 重量（克） |
| product_length_cm / height_cm / width_cm | int | 长/宽/高（厘米） |

> 品类是葡语（如 `beleza_saude`=health_beauty），题目要英文品类名就 JOIN `category_translation`。（⚠️ 库里这张表实际名字是 `category_translation`，**不是** `translation`）

### 7. sellers 卖家表（3095行）

| 字段 | 类型 | 含义 |
|------|------|------|
| seller_id | string | 卖家ID（**主键**） |
| seller_zip_code_prefix | int | 邮编前缀 |
| seller_city | string | 城市 |
| seller_state | string | 州 |

### 8. category_translation 品类翻译表（71行）

| 字段 | 含义 |
|------|------|
| product_category_name | 葡语品类名 |
| product_category_name_english | 英语品类名 |

## 四、高频业务口径（背下来）

| 要算什么 | 怎么算 |
|----------|--------|
| 订单数 | `COUNT(DISTINCT order_id)`（在orders表可直接COUNT） |
| 月度趋势 | `DATE_FORMAT(order_purchase_timestamp,'%Y-%m')` 分组 |
| GMV | order_items 的 `SUM(price)`，或 payments 的 `SUM(payment_value)` |
| 复购率 | 有≥2笔订单的 customer_unique_id 数 ÷ 总客户数（≈3.12%） |
| 配送时长 | `DATEDIFF(delivered_customer_date, purchase_timestamp)`（均值≈12.5天） |
| 准时率 | 送达时间 ≤ 预计时间的订单占比（≈91.89%） |
| 差评率 | `review_score <= 2` 的占比 |
| 有效订单 | 一般只统计 `order_status = 'delivered'`，看题目要求 |

## 五、自查小技巧

忘记表里有什么字段时，在VSCode里跑：

```sql
DESC orders;          -- 看某张表的结构
SHOW TABLES;          -- 看库里有哪些表
SELECT * FROM orders LIMIT 5;  -- 抽5行看真实数据长啥样
```

## 六、报错速查（踩过的坑）

| 报错信息 | 真正原因 | 怎么修 |
|----------|----------|--------|
| `Unknown column 'A, B' in 'field list'`（两个名字被逗号连在一起） | 逗号打成了**中文全角逗号** `，`，MySQL 把 `A，B` 当成一个列名 | 切英文输入法，把 `，` 换成 `,` |
| `Unknown column 'x' in 'field list'` | 外层引用了子查询里没产出的列 | 检查子查询 SELECT 有没有给这列起别名 |
| `Every derived table must have its own alias` | `FROM (SELECT ...)` 后面没起别名 | 补 `) AS t` |
| `Unknown column 'x' in 'on clause'` | JOIN 条件里的表别名写错，或等号两边是同一张表 | 两边必须是不同表，如 `c.x = p.x` |
| `In aggregated query without GROUP BY` | 用了聚合函数但把非聚合列裸着放进 SELECT | 用 `MAX()` / `ANY_VALUE()` 包住，或加进 GROUP BY |
| `You have an error in your SQL syntax ... near 'over'` | 连的是 3306（MySQL 5.7），不支持窗口函数 | 切到 3307 的 8.0 连接（桌面启动脚本） |
